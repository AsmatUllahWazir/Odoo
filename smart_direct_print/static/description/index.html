Intelligent Printer Rules

RULES ENGINE

Advanced rule-based printer selection with priority evaluation. Rules can be based on user, company, workstation, report, model, carrier, document type, or custom domain filters.

  • Priority-Based: Rules evaluated in priority order (highest first).
  • User-Specific: Assign printers to specific users or user groups.
  • Report-Specific: Different printers for different reports.
  • Domain Filters: Complex conditions using Odoo domains.
  • Fallback Logic: User default → Company default → Global default.

Detailed Operational Workflows & System Architecture

🖨️ Direct Printing Workflow

  • 1. User Action: User clicks Print button or triggers scenario.
  • 2. Printer Resolution: System evaluates printer rules in priority order.
  • 3. Report Rendering: Generate document (PDF, ZPL, etc.).
  • 4. Format Check: Verify printer supports the document format.
  • 5. Job Creation: Create smart.print.job record.
  • 6. Job Queuing: Job enters queue for processing.
  • 7. Server Communication: Send to print server via REST API.
  • 8. Status Update: Monitor and update job status.
  • 9. Notification: User receives success/error feedback.

📋 Printer Resolution Workflow

  • 1. Explicit Printer: User selects printer directly.
  • 2. Rule Evaluation: Check rules in priority order.
  • 3. User + Report Rule: Exact match for user and report.
  • 4. Workstation + Report: Match workstation and report.
  • 5. User + Model Rule: Match user and model.
  • 6. User Default: User's configured default printer.
  • 7. Company Default: Company-wide default printer.
  • 8. Global Default: First active printer in system.
  • 9. Fallback: Standard Odoo printing if no printer found.

🔄 Automatic Scenario Workflow

  • 1. Action Trigger: System action occurs (e.g., order confirmed).
  • 2. Code Detection: System detects action code trigger.
  • 3. Scenario Lookup: Find active scenarios for action.
  • 4. Condition Check: Evaluate condition filters on records.
  • 5. Printer Resolution: Determine printer for scenario.
  • 6. Job Creation: Create print job for each record.
  • 7. Auto-Send: Send jobs to printer automatically.
  • 8. Status Tracking: Monitor job completion.
  • 9. Notification: User notified of print completion.

📦 Shipping Label Workflow

  • 1. Label Generation: Carrier generates shipping label.
  • 2. Attachment Detection: System detects new attachment.
  • 3. Label Identification: Identify as shipping label.
  • 4. Printer Resolution: Find appropriate label printer.
  • 5. Format Detection: Detect label format (ZPL, PDF).
  • 6. Job Creation: Create print job for label.
  • 7. Auto-Print: Send directly to printer.
  • 8. Deduplication: Prevent duplicate printing.
  • 9. Status Update: Mark label as printed.

Enterprise Backend Configuration & Access Rights

Granular Security Groups Matrix

The module defines 3 distinct security access groups inside Odoo 19 User Settings. Each role strictly controls what the logged-in user can view, create, edit, or export:

Security Role Intended Staff Role Permissions & Capabilities
Print User Regular Staff View printers, create print jobs, view own jobs, use print wizards.
Print Manager Department Managers Manage printer rules, create scenarios, view all jobs, manage printers.
Print Administrator IT/System Administrators Complete control over print servers, all configurations, user management, and system settings.

System Configuration Parameters

  • Print Server: URL and API key for print bridge service.
  • Default Printer: Company-wide default printer selection.
  • Print Timeout: Configurable timeout for print operations.
  • Retry Attempts: Maximum retry attempts for failed jobs.
  • Default Copies: Default number of copies for new jobs.
  • Auto-Print: Enable/disable automatic printing globally.

Key Data Models

  • smart.print.server: Print server connection configuration.
  • smart.printer: Physical printer with capabilities.
  • smart.print.job: Print job with status tracking.
  • smart.print.rule: Printer selection rules.
  • smart.print.scenario: Automatic printing scenarios.
  • smart.print.report: Report configuration for direct printing.

Integrations & External APIs

🔗 Odoo Native Integrations

  • Sales (sale): Print sale orders on confirmation.
  • Purchases (purchase): Print purchase orders on confirmation.
  • Accounting (account): Print invoices on posting.
  • Stock (stock): Print delivery slips on validation.
  • Delivery (delivery): Print shipping labels automatically.
  • Reports (ir.actions.report): Enhanced report printing.
  • Attachments (ir.attachment): Direct attachment printing.

📡 External Print Bridge API

  • Health Check: GET /api/health - Server status.
  • List Printers: GET /api/printers - Available printers.
  • Print Document: POST /api/print - Send print job.
  • Job Status: GET /api/status/{id} - Check job status.
  • Cancel Job: POST /api/cancel/{id} - Cancel print job.
  • Authentication: Bearer token with API key.

Extension Points (For Developers)

  • Printer Resolver: Override get_printer_for_document() for custom logic.
  • Scenario Actions: Add custom actions with unique codes.
  • Document Formats: Extend supported document formats.
  • Print Server: Implement custom print server integrations.
  • Webhooks: Add webhook support for external systems.
